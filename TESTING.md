### Bug found & fixed during this pass

**Issue:** The AI Studio-issued `GENAI_API_KEY` is scoped only to
`generativelanguage.googleapis.com` (Gemini), not `translate.googleapis.com`.
Caregiver alert translation (`translate_text`) was hitting `401 Unauthorized`
on that key and — unlike the Gemini call path — had no ADC retry, so it
silently fell back to `[MOCK-ES] ...` output. This would have failed
spec.md Section 4.9 (no mock output in the judged demo) if left unfixed.

**Fix:** `_translate_cached` in `app/services/ai_services.py` now mirrors
`_call_gemini`'s fallback chain: API-key REST call → Vertex/ADC Cloud
Translation client → mock (only as a last resort, and only under
`USE_MOCK_AI=true` or a total outage). Verified via Cloud Run logs after
redeploy: the Spanish alert subject now reads *"Alerta de crisis: Su ser
querido podría necesitar apoyo"* — a real translation, not `[MOCK-ES]`.

## Known Gaps

- Voice-first crisis trigger (Cloud Speech-to-Text) is architected (spec.md Section 3.1/3.7) but not yet wired to a live microphone input in the UI — trigger_method="voice" is supported by the API.
- Wearable/passive signal integration is a stretch goal (spec.md Section 7), not built.
- Multi-caregiver coordination (more than one linked caregiver) is a stretch goal, not built.
- The backend uses an **in-memory data store** — every Cloud Run redeploy wipes all profiles/crisis history. Demo profiles must be (re-)created live after any redeploy, which conveniently also satisfies the "no pre-seeded data" requirement in spec.md Section 4.9.
- The `GENAI_API_KEY` currently in use is scoped to Gemini only; Cloud Translation automatically falls back to Vertex AI/ADC (see bug fix above) rather than a dual-scoped key. Functionally equivalent for the demo, but worth broadening the key's API restrictions later for a single, direct-REST code path.
